# UI redesign: build plan

The approved design is `final/` (open `final/index.html`). `BRIEF.md` records the decisions and `REVIEW-professional.md` the professional-grade review that was applied. This plan turns the mock-ups into the product in stages, one PR each, so every stage can be reviewed, merged and used before the next starts.

## Principles

- **The mock-ups are the reference, not the code.** `final/obiter.css` is not shipped. Each stage rebuilds the screen with Tailwind v4 and the `@obiter/ui` primitives, matching the mock-up at 1440 × 900 and 1024 × 768 in both themes.
- **Contract first.** Token names in `docs/specs/app-shell/contract.md` are frozen; values may change. New tokens, new primitives and the new frame go through the contract's change process in the stage that ships them, so the contract never describes something the code does not do.
- **Phosphor stays.** The mock-up sprite (`final/icons.svg`) is a guide to which glyph goes where; the product uses the nearest Phosphor icon, as the contract requires. The Obiter mark is the one exception: it ships as a brand asset in `packages/ui/src/brand/`.
- **No fake product state.** A mock-up element ships only when real data backs it. Elements without a backend are left out of the stage and listed below; each needs its own spec before it is built.
- **Dead code goes in the same PR.** A stage deletes every component, hook, token, style and test that its new screen replaces. Before opening the PR, run `bunx knip --workspace <touched workspaces>` (ad hoc, not a committed dependency) and remove what it finds unused in the touched area. The PR summary reports lines added and deleted.
- **No behaviour change hidden in a restyle.** Data loading, routes, auth and legal-critical logic stay as they are unless the stage says otherwise. Existing tests keep passing; tests that only assert old markup are rewritten against the new markup, not deleted.

## Not built until specified

These appear in the mock-ups but have no backend today. They are left out of their stage, and the stage's PR says so.

- **Matter activity log** (actor, action, version, time). Only Redact runs have an audit endpoint.
- **"Assigned to you"** on the dashboard. There is no assignment model.
- **Artefacts** on the matter page. Waits for the Matter Artefacts build (spec merged in #347).
- **Data region** in settings. It must show the configured region (`RULES.md` requires EU hosting), not a hard-coded label.
- **Dismiss finding with a reason**, and the Verify version binding, if the verification API does not already store them. Stage 9 checks and either adds them to the API with tests or leaves them out.
- **Pinned matters** need somewhere to persist. Stage 2 uses the existing preference storage if it fits; otherwise the sidebar shows recent matters until pins are specified.
- **"Preview disclosure copy"** and the review-every-page step in Redact finalise, if the output API cannot render a preview yet.

## Verification per stage

- `bun run typecheck`, `bun run lint` and the tests of every touched workspace.
- Screenshots of the running app at 1440 × 900 and 1024 × 768 in light and dark, attached to the PR beside the matching mock-up.
- Keyboard pass on the changed screens: focus order, visible focus, Escape closes panels and returns focus.
- Stages 6 to 9 touch legal-critical screens: their PRs include the failure path (failed run, stale check, undecidable move) as well as the happy path.
