# App Shell Component Contract

> **Freeze artifact.** This document defines the stable surface the Redact review UI ([PRD 2](../../prds/archive/redact-2-review-output.md)) and every future feature UI builds against. It freezes at the end of Milestone 1 of the [App Shell Rebuild PRD](../../prds/archive/app-shell-rebuild.md). After freeze, any change here requires updating **both** this contract and Redact PRD 2, and is owned by the plan owner.

The Redact review UI imports only from `@obiter/ui`, `@obiter/app-shell` public exports, and `@obiter/contracts`. It never imports shell-internal modules.

## Change process

1. A needed primitive/token/route is missing or wrong → raise it against this doc, not against shell internals.
2. Plan owner updates this contract **and** the corresponding section of Redact PRD 2 in the same change.
3. Both tracks move together. No silent contract drift.

---

## 2. Design tokens (`--obiter-*`)

Source of truth is `packages/ui/src/tokens.css`, consumed by Tailwind v4 via `@theme`. `@obiter/ui/tailwind.css` imports with `source(none)`, so every app declares its own source trees with `@source`: automatic detection scans whatever is on disk, and in the production image build (no `.gitignore`) the SSR pass rescanned the client pass's `dist/` output and named a stylesheet the client never emitted. **Token names are frozen; values may tune within the same theme.** Light is the token default (`:root`); dark is an explicit `[data-theme="dark"]` override. Both themes must render every screen correctly (FR6). Light is the default the product renders; the saved choice is light, dark, or **match system**, and matching the system follows `prefers-color-scheme` live (a media-query subscription, not an effect on derived state).

### 2.1 Color (semantic, defined per theme)

`--obiter-bg`, `--obiter-surface`, `--obiter-surface-raised`, `--obiter-border`, `--obiter-border-strong`, `--obiter-text`, `--obiter-text-muted`, `--obiter-text-subtle`, `--obiter-brand`, `--obiter-brand-fg` (text on brand), `--obiter-brand-pressed`, `--obiter-ring` (focus ring), `--obiter-overlay` (scrim).

The canvas is `--obiter-canvas`: the solid colour behind every pane, warm in light and darker than the panes in dark. Additional surfaces: `--obiter-inset` (charcoal document surround in dark), `--obiter-fill`, `--obiter-fill-hover`, `--obiter-paper`, `--obiter-paper-ink`, `--obiter-paper-muted`. Paper stays near-white in both themes. Interaction washes: `--obiter-hover`, `--obiter-brand-hover`, `--obiter-brand-soft`. Status tints: `--obiter-status-{info,success,warning,danger}-soft`.

### 2.2 Status (defined per theme, each with `-fg` for text-on-fill)

`--obiter-status-info`, `--obiter-status-success`, `--obiter-status-warning`, `--obiter-status-danger` (each with a matching `--obiter-status-*-fg`).

### 2.3 Redaction span-category palette — CONTRACT SURFACE

Each category is defined as a **`-bg` / `-fg` pair** so highlighted span text meets WCAG AA contrast in **both** light and dark themes, and categories are distinguishable by hue. A bare `--obiter-span-<category>` alias (= the `-bg` value) is also exported for the PRD's literal naming.

Categories (15 — the full `spanCategorySchema` set; `date` and `secret` were missing from the first draft and are required by PRD 2's FR5 color mapping):

### 2.4 Spacing, radius, elevation, type

- **Spacing:** `--obiter-space-{0,4,8,12,16,24,32,40,48,56}` in pixels, mapped to the corresponding Tailwind 4px-grid utilities. `--obiter-row-height` is 52px; `--obiter-control-{compact,default,large}` are 28/32/40px; `--obiter-panel-width` is 380px; the command palette's own surface uses `--obiter-palette-width` (36rem) and `--obiter-palette-offset` (its top inset).
- **Radius:** `--obiter-radius-sm | md | lg | xl | pill` (exposed as `--radius-*`).
- **Elevation:** `--obiter-shadow-sm | md | lg`, tinted to the background hue (no harsh black drop-shadows).
- **Type:** `--obiter-font-sans`, `--obiter-font-mono`, `--obiter-font-serif` (paper and auth display panel only), and weight tokens `--obiter-font-weight-*`. Six `--obiter-text-{page,section,item,body,meta,caption}` levels, each with `-line-height`, `-weight`, `-tracking`: 28/600/1.2, 18/600/1.3, 14/500/1.4, 14/400/1.55, 13/400/1.45 muted, 12/400/1.4 subtle. Only page/section titles have tracking (−0.02/−0.01em). Exposed as `text-page` through `text-caption`; semantic colour remains explicit.

## 3. `@obiter/app-shell` public exports

### 3.1 `useCurrentUser()` — real `/api/me`

```ts
export function currentUserQueryOptions(): QueryOptions<MeResponse> // for route loaders
export function useCurrentUser(): UseSuspenseQueryResult<MeResponse> // for components
```

Backed by the real `GET /api/me`. Unauthenticated → the session/redirect layer sends the user to `/sign-in` (FR1). No demo me response exists on this path.

### 3.2 `apiFetch()` — auth + typed errors

```ts
export class ApiError extends Error {
  readonly code: ApiErrorCode // from @obiter/contracts apiErrorCodeSchema
  readonly status: number
  readonly requestId: string
}
export function apiFetch<T>(input: string, init?: RequestInit): Promise<T>
```

- Sends credentials (`credentials: 'include'`) so the better-auth session cookie travels.
- On non-2xx, parses the body through `apiErrorResponseSchema` and throws `ApiError` with the typed `code` (never a silent fallback).
- On 2xx, returns the parsed JSON as `T`.

### 3.3 Shared `QueryClient`

Provided at the app root via the TanStack Router context (already wired in `apps/web/src/integrations/tanstack-query/root-provider.ts`). `useCurrentUser()` and all shell queries run on that client. Feature UIs use `useQueryClient()` / `queryOptions` like the shell does — they do not create their own client.

### 3.4 Auth client

Sign-in is real, via `createAuthClient({ baseURL })` from `better-auth/client` with the matching `magicLink` client plugin. The shell exposes a `useAuth()` surface (`signIn`, `signOut`, `useSession`) that wraps it; feature UIs should not call better-auth directly. Email/password and magic-link are both supported (the API enables both).

## 4. Routes

- **Document detail (owned by this track):** `/matters/:matterId/documents/:documentId` — a **layout route** that renders document metadata + the redaction-runs region (list + "Create Redaction Run" CTA) and exposes a child `<Outlet />` for feature sub-routes.
- **Feature sub-route (owned by Redact PRD 2):** `redact/$runId` nests under the document detail layout route. The shell provides the parent chrome and the outlet; it does not implement the review screen.
- **Search query parameter:** `/search` accepts an optional `q`. Both routers validate it, the view runs that search on load, and both the command palette and the contents panel's stored recent searches link through it. A `/search` link without `q` still opens the empty search view.

In TanStack file-routing terms:

```
apps/web/src/routes/matters/$matterId/documents/$documentId.tsx   (layout: chrome + <Outlet/>)
apps/web/src/routes/matters/$matterId/documents/$documentId/redact/$runId.tsx   (Redact track)
```

### 4.1 Access requests (`/request-access`)

Closed sign-up. Accounts start with an enquiry the API verifies; nothing on these routes needs a session, and both are rendered outside the shell chrome.

- **`/request-access`** — name, work or university email, category (three cards: legal professional, law student, academic researcher), country (England and Wales, Scotland, Northern Ireland), organisation name, an option to set up the organisation as its admin, and three attestations under "Terms and privacy" (accepts the terms of service and has read the privacy policy, both linked to obiter.si, and the details are true). The shared webmail and obvious non-UK academic lists live in `@obiter/contracts` (`isFreeWebmailAddress`, `isObviousNonUkAcademicAddress`), so client and API refuse the same addresses; anything subtler is the API's decision. Success renders "Check your inbox" naming the address.
- **`/request-access/confirm?token=…`** — sends the token to the API and renders one of four outcomes: verified (with the next step: account set-up or sign-in), pending review, expired, or invalid. A link with no token renders invalid without calling the API. Account set-up is a form on that page (name, the confirmed email, password and confirmation) that calls the auth client's email sign-up; the API admits only an address with a verified request or a valid invite, and its refusal is shown on the form. Success shows "Check your inbox": the account is usable once the emailed verification link is followed, which signs the user in.
- **`/sign-up`** — retired. It redirects to `/request-access`, and a token on the query (`/sign-up?token=…`, the shape older invite links carry) is forwarded to `/invites/accept`. The redirect replaces the history entry so Back does not bounce.
- **Contracts** — `packages/contracts/src/access-request.ts`: `createAccessRequestInputSchema`, `createAccessRequestResponseSchema` (`status: 'confirmation_sent'`), `confirmAccessRequestInputSchema`, `confirmAccessRequestResponseSchema` (discriminated on `status`). The submission schema is strict and has no field for a regulator number or any evidence: proof of standing is never collected. `webmail_address`, `non_uk_address`, `rate_limited` and `invalid_request` join the shared `ApiErrorCode` set; the client maps each to fixed copy and falls back to the API's own message.
- **Planned API routes** — `POST /api/access-requests` and `POST /api/access-requests/confirm`. Until the API serves them the form shows the refusal it receives and creates nothing.
- **The confirmation POST runs from the browser, not the server render.** `confirmAccessRequestQueryOptions` is disabled while `window` is absent, so rendering the page on the server cannot be the side effect that consumes a token. The query is `staleTime: Infinity` and does not refetch on mount, focus or reconnect; a reload re-confirms, which is idempotent by token.

## 5. Page scaffold

A layout primitive feature screens compose instead of building their own frame:

```ts
export function PageScaffold(props: {
  title: ReactNode
  eyebrow?: ReactNode // quiet line above the title: Home's date
  description?: ReactNode // one line under the title: what the page is for
  actions?: ReactNode // slot for buttons/links in the header
  children: ReactNode // the content region
  className?: string
  compact?: boolean // one-line heading for pages that are worked in, not read
}): JSX.Element
```

Renders the approved page heading on the frame's content column: title at 28/600 with −0.02em tracking, description at body size on a 68ch measure, header actions vertically centred against the title and stacked below it when the pane is narrower than 1088px, 56px top and bottom padding, and a 40px gap between content sections. Content stops at 1216px; the gutter is 48px, and 32px when the pane is narrower than 896px. **Page layouts measure the pane, not the window.** The main content pane is a CSS container (`container-type: inline-size`, Tailwind `@container`), and page-level layout uses container variants — 896px (`@pane`) for the gutter, 1088px (`@pane-wide`) for side-by-side headers and two-column pages, 1248px (`@pane-full`) for a third column. Viewport breakpoints stay in the shell only (rail, bottom bar, overlay), because the space a page gets now depends on the sidebar, the contents panel and the right slot rather than on the window. The document workspace is excluded: its pane is not a query container, so the paper page keeps rendering exactly as it did. There is no uppercase label above the title. The optional eyebrow is quiet metadata (Home's date, `Monday 26 Oct 2026`), which the dashboard mock-up places above the greeting; it aligns on the same left edge as the title. A page whose heading is a working surface passes `compact`: the name drops to 18/600 and sits on one line with its quiet meta (a matter's reference and status) and the actions at the end, with 32px top and bottom padding; the description and the domain tags move into the page's own detail card. The matter page is the only page that uses it today. Screens that are working surfaces rather than pages do not compose it: the Redact review screen carries its own document header (filename as the title, matter and review state beneath, actions at the end) on the frame's content gutter, because a reviewer works in it for the length of a run and the approved mock-up sets it at document scale. The Redact finalised screen is a page and does render inside `<PageScaffold>`.

## 6. App frame

`<AppShellLayout>` renders the workspace chrome the approved design describes, driven by real `useCurrentUser()` data:

- **Canvas and panes.** One solid canvas (`--obiter-canvas`: warm in light, darker than the panes in dark) with no grid or texture. Work areas sit in 14px-radius panes with a 1px hairline border on an 8px gutter. The sidebar or rail spans the full height of the window on the left, so the title bar is the top row of the right-hand column. Inside a section, the contents column and the page are **one** pane split by a hairline: the page on `--obiter-surface-raised`, the contents column one shade off it on `--obiter-surface`. The page in that pane is the layout container every page-level container query reads.
- **Sidebar, Home only.** 236px, drawn straight on the canvas rather than in a pane: the Obiter monogram with the organisation name level with the title bar, a `Search Obiter` field with its ⌘K / Ctrl+K hint on the row under it, the modules Home, Matters, Search, Verify and Redact with their counts and alert dots, an Agent row that toggles the right slot and shows its shortcut, recent matters, then settings, theme and account at the foot. Research has no route, so no entry is invented for it. Counts come from queries the frame already runs and follow one rule (`packages/app-shell/src/open-work.ts`): active matters; open findings on each document's newest Verify run, plus one for a run that stopped; and redaction runs awaiting a decision. A module whose count has no cheap source shows no count.
- **Rail.** Every other section, and Home once the sidebar is collapsed: a 46px icon column with a labelled control per module and a tooltip naming the module and its shortcut. The count moves into the accessible name and the alert dot. An Agent control with the right-slot shortcut, settings, theme and account sit at the foot. At 767px and under the rail becomes a bottom bar.
- **Title bar**, 40px, on the canvas: the top row of the right-hand column, so its controls start exactly at the pane's left edge and move with the sidebar, with the contents panel and on narrow layouts, without a hard-coded offset. Left to right: the sidebar toggle, back and forward, the breadcrumb (`Organisation › Module › current`), and, only while the sidebar is a rail or a bottom bar, the search trigger at the far right with its ⌘K / Ctrl+K hint — otherwise the sidebar's own `Search Obiter` field carries it, so no screen shows two.
- **Command palette.** The search trigger opens one Base UI dialog over the whole shell, and so does ⌘K / Ctrl+K from anywhere, including a text field. It is the app's only app-search surface — there is no second dropdown. One input filters grouped rows: **Recent** (the recently opened document, then matters by last update) while the input is empty; **Go to** matters (name, reference), documents (name, matter), Verify runs and redaction runs, from the queries the app already runs; **Create** new matter, upload document, new blank document and start redaction, where upload and new blank document go into the open matter or ask which matter when none is open; **Actions** sidebar, agent panel, focus mode, theme and each Settings section, showing the shortcut the shared helper formats for the platform; and last **Search** — "Search case law and legislation for '…'" — which opens `/search?q=` with the typed query. Arrow keys move, Enter opens, ⌘/Ctrl+Enter opens a link row in a new tab, Escape closes and returns focus to whatever opened the palette. Rows that navigate are links, and matching is a local subsequence scorer, not a new dependency.
- **Matter switcher.** Inside a matter, the matter's crumb is a button rather than a link: a Base UI menu with a filter input at the top, up to eight recent matters with their references, the current matter marked with a brand dot, and All matters. Choosing one opens that matter's page, and Escape returns focus to the crumb.
- **Document header.** There is none: the page opens straight onto the ribbon. The matter tab names the open document and carries its save state, so no row above the ribbon repeats the filename and no back arrow, matter name, save button, track-changes switch or verify chip appears — the breadcrumb and the contents panel say where the document is, and the ribbon carries the actions. The redaction mark for a redacted stored version sits in the PDF viewer's ribbon and, for a Word document, in the document information panel and every list the document appears in.
- **Ribbon.** A tab row (File, Edit, Insert, Format, Review, View) sits above the ribbon panel, and the tabs are real tabs: exactly one is selected, Format holds the character, paragraph, list and style commands and is the default, and the panel under the tab row shows that tab's command groups with each group captioned. The tabs are a `tablist` of `tab` controls over one `tabpanel`; the arrow keys, Home and End move between them and only the selected tab is in the tab order. File is not a tab but a menu, because it holds export, versions and redaction rather than a setting a ribbon suits. Save, undo and redo stay pinned to the left of the panel on every tab, so the quick-access controls never disappear, with each platform shortcut in its tooltip, the ⌘ glyph only on macOS, and Save disabled when there is nothing to save. A group whose commands are numerous or rarely used offers them from a small menu in that group — an icon with a caret, named for the commands it holds — so every tab's panel fits the ribbon without sideways scrolling at 1440×900; narrower panels scroll. A command that already has a control elsewhere on screen is not repeated as a ribbon button: undo and redo live in the quick-access trio, and the character, list and marking commands that the Font, paragraph and page panel owns stay in that panel, which the Format tab's `Font, paragraph and page` command opens. A disabled command gives its reason as its tooltip rather than as a second line of text. Track changes is a toggle command in Review › Tracking, and while tracking is on a compact `Track changes on` indicator sits at the right end of the ribbon so it cannot be on unnoticed. Review › Checks carries the verify status (`Not checked`, `Checked · version 2 · 1 flagged`, `Checking…`) as the status of Verify citations, which opens the findings for the stored version and is always available, and Check citations, which starts a run and is disabled with the reason whenever a run cannot start (unsaved edits, an unavailable or unready document, a run already starting). Review's Comments command, Check defined terms and Check cross-references open the right slot on its Comments or Checks tab rather than a docked panel of their own, so each list has one home: the command shows as on while that tab is open, Check defined terms and Check cross-references scroll the Checks tab to their section, Comments again closes the slot, and closing it from the command or with Escape inside the tab returns focus to the command that opened it. Escape closes the slot only when a command opened it, since a slot opened from its own tab has no control to return to. Commenting on a selection opens the Comments tab with the selection as the new comment's anchor and leaves it open if it already is. Document information, Verify, Track changes review and List of authorities stay docked panels.
- **Presence avatars.** The tab strip shows up to three initials avatars of the other people in the active document, at the right end of the strip beside its controls, each tooltip naming the person and whether they are viewing or editing, and `+N` beyond three. They render only while a document tab is the active tab. Names resolve from the organisation member list; the presence data is the existing collaboration sync, and the open workspace publishes it to the strip rather than the strip querying it. Nothing renders when you are alone. The toggle collapses the full sidebar on Home and hides or shows the contents panel everywhere else; one toggle for the sidebar and none for the right slot, which has its own Agent row instead, and no chevron inside the contents panel. Both choices are remembered per person (`obiter.sidebar.collapsed`, `obiter.contents.hidden`), read and written inside `try`/`catch` so a blocked storage API leaves the shell working. On desktop the row is the window drag region; its controls are no-drag, and on darwin the sidebar's own top-left is padded so the monogram clears the traffic lights.
- **Contents panel**, per section, joined to the page in the same pane with its header row on the 40px tab-strip line: Matters shows the Active/Archived/All filter the page applies plus recent matters; a matter shows its name and reference, its documents, and the Verify and Redact runs the API links to it; Verify and Redact group runs by status with attention first; Search lists the recent searches the search view already stores; Settings carries the section nav the page used to own. At 1023px and under it opens as an overlay from the same toggle, with a scrim, Escape, and focus returned to the toggle.
- **Matter tabs.** Inside a matter the top of the page column is a 40px tab strip (`matter-tab-strip.tsx`), level with the contents panel's header row and on `--obiter-surface`, with the active tab on `--obiter-surface-raised` and joined to the page below it. The strip's left inset matches the ribbon row below it, so the tab icons and the File, Edit and Insert labels share one left edge. The route is the source of truth: the tab strip lists the matter overview, the documents open in this matter, the matter's Verify view (`/matters/:matterId/verify`) and its redaction runs (`/matters/:matterId/redact/:runId`) — the overview is a home icon rather than a tab that repeats the matter name, named in its tooltip and its accessible name, and pinned, so it carries no close control in the strip or its context menu — and the current tab follows the URL, and a tab set is remembered per person per matter under `obiter.matterTabs.<userId>.<matterId>` (`matter-tabs.ts`), read and written inside `try`/`catch`, capped at 12 with the overview pinned and the oldest unpinned tab closing. A single click in the contents panel opens a preview tab (italic) that the next single click replaces; a double click on the tab, an edit to the document, or opening it from the + menu makes it permanent. Closing the current tab moves to its neighbour, and the last tab falls back to the overview. ⌘/Ctrl+1–9 select, ⌘/Ctrl+W closes and ⌘/Ctrl+Shift+T reopens the last closed tab **on desktop only** — browsers reserve those combinations for their own tabs, so the web build leaves them to the browser — and all three are ignored while the target is typing. At 767px and under the strip collapses to one “N open” switcher that names the active tab and shows its save state.
- **Save state.** A document tab carries the save state of the document it names, published by the open workspace into the tab strip's registry (`document-tab-status.tsx`) so there is one copy of it. `Saved` shows nothing; unsaved work shows a 6px ink dot, a save in flight the same dot pulsing (and still under `prefers-reduced-motion`); a failed save, an offline tab and a newer version on the server show a small danger-coloured warning icon; saved work whose history needs reloading shows the warning-coloured one. Hovering or focusing the indicator shows the explanation and the version number the header used to show, the tab's accessible name reads `<filename>, <state>` whenever the state is not `Saved`, and a read-only tab adds nothing. The narrow switcher shows the indicator beside the active tab's name and beside each entry in its menu.
- **Document actions.** The document the tab names can be deleted from that tab's context menu, reached by keyboard with the context-menu key or Shift+F10, and from the strip's “All open tabs” menu for the active document; both open the same confirmation dialog, which stays open with the error when the request fails. Both entries appear only for an owner or admin. The + menu creates a blank document, uploads documents, starts a Verify run or starts a redaction run through the flows that already exist, with single-letter accelerators shown while it is open. A document tab can be opened to the side, by dragging it to the pane's right edge or from its context menu, which records `?side=<tab>` in the URL. The split starts at 50/50, the divider drags between 30 and 72 percent, double-clicking it or using its arrow keys returns to even, and closing either side returns to one. The two panes share the divider's width, so an even split gives them the same margins. Both sides render the paper at one scale, fitted to the narrower side's desk content width — its pane less the desk's padding and any scrollbar — and the editing side's View > Zoom multiplies that shared scale, so the two papers are the same size and neither scrolls sideways at 100%. The read-only side reserves the ribbon's height, so both pages start on the same line. Each side carries its own compact header row — the name and `Read only` with the version in its tooltip — and its own scroll. The side stays read-only because the draft store, the save owner, the presence heartbeat and the workspace shortcuts are single-document; a Swap sides action in the read-only header makes that document the one you edit instead.
- **Right slot.** A docked 330px pane with the tabs Agent, Comments, Checks and History and one tab open at a time. The open tab shows its icon and name; the others show their icon alone, keep their name as their accessible name, and name themselves in a tooltip on hover or focus, so four tabs fit at 330px without touching. Arrow keys move between tabs and only the open tab is in the Tab order. A tab is listed only where the shell registry (`packages/app-shell/src/right-slot.tsx`) registers it for the current route, so a route gains a tab by registering content rather than by adding chrome. Agent is registered everywhere; Comments, Checks and History are registered on matter document routes (`/matters/:matterId/documents/:documentId`) and nowhere else. A remembered tab the route does not register shows Agent without overwriting the stored choice. Open state and the chosen tab are remembered per person (`obiter.rightSlot.open`, `obiter.rightSlot.tab`). The open document can ask the shell to show one of its tabs or to close the slot (`RightSlotPortalProvider`'s `onShow`), which also leaves focus mode. ⌘J / Ctrl+J toggles it, and so does the Agent row in the sidebar or rail, whose tooltip names the shortcut; at 767px and under it opens as a bottom sheet above the bottom bar.
- **Document tabs.** The document page owns the data, so the shell does not fetch it again: each document tab is an outlet (`right-slot-portal.tsx`) that the open document renders into through a React portal, keeping the workspace's own state and contexts. The workspace computes the checks only while the Checks tab is open. Until the page fills a tab it reads `Opening the document…`. **Comments** lists the document's threads from the existing comments API — open threads, then resolved, then those imported from the Word file — with Show in document, reply, resolve, reopen, granted thread deletion and a Deleted comments view with restore, and adds a comment to the current selection; it is the only comments list, and the ribbon opens it. **Checks** groups the results of the existing client-side checks — defined terms, cross-references, and authorities with their latest Verify state — and each finding moves the caret to its paragraph; with nothing to report it shows one `No findings` state. Both need the editable Word workspace: on a PDF or text file, a document still being prepared, a document that failed to open, or while an earlier version is open, they say why and, for an earlier version, offer Back to the current version. **History** lists every saved version newest first with who saved it, when, its size and whether it is current, the original upload or redacted. Choosing an earlier version opens it read only in the page, marked as the one shown; choosing the current version returns to editing. Versions still processing cannot be opened. Restoring a version is not offered: no action for it exists. Each tab has loading, empty and error states.
- **Agent tab.** Outside a matter it says the agent works on one matter at a time and offers no ask box. Inside a matter it shows an ask box with the matter as a context chip and, on a document route, the open document as a second chip the person can remove. ⌘Enter / Ctrl+Enter asks. Under the box a line says what leaves Obiter: the question always goes to the model provider; matter documents go only when the organisation allows it. A run shows its goal, a summary line ("Worked for 41s · read 3 sources"), each step as it streams, and then the answer, the refusal or the failure. Every answer sentence carries numbered pointers; a case-law pointer opens the judgment at that paragraph and a document pointer opens the matter document, with the cited passage quoted under Sources. A refusal names its rule and the missing setting, with a link to the Agent settings (`/settings?section=organisation#settings-agent`). A live run has a Cancel button. Below the box the matter's runs are listed newest first with their status. The data is `@obiter/contracts` `agent-run`, `agent-trace` and `agent-api`; the step stream is server-sent events read with `fetch`, so the desktop bearer token is sent, and the run is refetched while it is live in case the stream drops.
- **Agent setting.** Settings → Organisation shows the configured model and a switch, off by default, that lets owners and admins allow matter documents to be sent to the model provider. Members see the state read-only.
- **Keyboard shortcuts** live in one module (`shell-shortcuts.tsx`) and are shown in tooltips with `KeyboardHint`: ⌘K or Ctrl+K opens the command palette, ⌘\ or Ctrl+\ toggles the sidebar, ⌘J or Ctrl+J the right slot, ⌘. or Ctrl+. focus mode, and `g` then `h`, `m`, `v`, `r` or `s` goes to Home, Matters, Verify, Redact and Search. Bare letters are ignored while the target is typing, and a key the editor or a dialog has already claimed (`defaultPrevented`) is left alone. The 800ms sequence window is the only timing.
- **Key labels and the primary modifier follow the platform** (`keyboard-platform.ts`). A Mac — the macOS desktop build, or a browser that reports `darwin` through `userAgentData`, `navigator.platform` or the user agent — shows ⌘, ⇧ and ⌥, and matches `metaKey`; every other platform shows Ctrl, Shift and Alt, and matches `ctrlKey`. The other modifier never triggers a shell shortcut. A Mac glyph sequence is written without separators (`⌘⇧Z`), elsewhere with `+` (`Ctrl+Shift+Z`). The server renders the non-Mac label and the browser corrects it on hydration.
- **Focus mode** hides the rail, the contents panel and the right slot, leaving the title bar and the page. ⌘. or Ctrl+. toggles it, Escape leaves it and returns focus to the title-bar toggle, and it is not remembered across reloads.
- **Account menu** is a Base UI Menu anchored under the avatar in the sidebar or rail foot: name, email and role, Account settings, Sign out. Enter/Space/ArrowDown open it and move focus into the list, arrow keys and Home/End move between items, Escape closes it and returns focus to the avatar, and Tab or a click outside closes it — all from Base UI, not reimplemented in the shell.
- **Settings sections are addressable.** The section is the `section` search parameter of `/settings` (`account`, `security`, `organisation`, `preferences`; `validateSettingsSearch` in `settings-sections.ts`, registered by both routers), so a link can land on one: the contents panel's section rows are links, the command palette's settings actions navigate to them, the account menu opens `section=account`, and the links about naming the workspace, inviting people or creating an organisation open `section=organisation`. A missing or unknown section opens Account. Every section stays mounted, so moving between them keeps an unsaved draft. Organisation includes the Updates policy, where owners and admins can require updates.
- **The matters status filter** lives in shell state shared between the contents panel and the page (`shell-contents.tsx`), not in the URL, so every deep link still opens its route and the panel can drive the filter the page applies.
- **Shell states**: a session-check loading screen that names what it is doing; an error surface that says what is preserved and offers Retry (the route reset); not-found and permission-denied surfaces, chosen from the typed `ApiError` code (a refusal is not an error to retry); and an offline banner shown only when the browser reports no connection, which claims only that already-open pages stay readable and that saving, uploads and search will fail until it returns.
- **Theme**: light is the default (`:root`), dark is `[data-theme="dark"]`. The stored choice is `light`, `dark` or `system` (`obiter.theme.v2` in `localStorage`), resolved to the rendered theme and applied from each document root before first paint so a dark preference does not flash light. `system` follows `prefers-color-scheme` live. `useAppTheme()` returns the theme being rendered and `useThemeChoice()` the stored choice; the sidebar or rail toggle stores an explicit theme, and Settings → Preferences offers all three. Auth routes follow the theme; they do not force night. There is no floating Agent widget.
- **Auth screens** (`/sign-in`, `/request-access`, `/request-access/confirm`, `/sign-up`, `/forgot-password`, `/reset-password`, `/invites/accept`) share one centred layout with no illustration: the Obiter mark and name centred at the top with the theme toggle in the corner, the centred heading and description, then the form in a rounded card (`--obiter-surface-raised`, 1px hairline) in a 420px column anchored near the top so switching sign-in modes does not move it. Below the card sits the screen's link line; at the foot of the page, the screen's one footnote line and the legal links (Privacy policy and Terms of service on obiter.si, opening in a new window) with the copyright. The enquiry form widens its column to 480px so the three category cards read as cards. Desktop has no access request screens: its sign-in has no request-access link and those routes redirect to sign-in. There is no session-expired screen: the product has no such state, so no route or view is invented for it.

## 7. Invariants the shell must not break

- Organisation rename is owner-only, enforced by the API (`requireOwnerRole` plus an ownership check against the caller's own organisation). The client sends no organisation id in `PATCH /api/organisations`: an id in the request could only be meant to address another tenant.
- Draft state is per workspace. Each workspace builds its own `format` draft state rather than sharing `emptyFormatDrafts`, because `planDocumentSave` fills a copy in place; sharing the singleton would leak one workspace's paragraph styles into every other one.
- Tracked-change decisions and classification markings (Document type, Draft, Privileged, Without prejudice) each commit a new immutable version server-side, so both are refused while unsaved, blocked, stale or failed work would leave the base version behind.
- A refused find-and-replace batch never half-applies: the state is immutable, so a refusal returns its reason and changes nothing.
- Password change is verified server-side; the client-side checks are a courtesy the API repeats.
- A permission refusal is not an error to retry: the shell chooses its surface from the typed `ApiError` code.
- Verification findings and the legal checks are presented as things a person should look at, never as a verdict; honest uncertainty is surfaced, not passed silently.

## 8. Rules no unit test can reach

These rules were in code comments until the no-comments rule (29 Oct 2026). A unit test cannot observe them, so they are stated here; change them only deliberately.

- Restoring the last draft unmounts the save banner, so focus moves back to the document rather than being stranded on a removed node (`save-banners.tsx`).
- Focus returns to the caret's field at the only point a save can begin (`use-document-save.ts`).
- Save containment probes the most recent slots first (`use-document-save.ts`).
- While a save is still landing at the version boundary, Save stays visibly active rather than reading as inert (`use-document-save.ts`).
- The track-changes toggle is sent only while a flip is pending, so a stale tab cannot revert a collaborator's setting (`use-document-save.ts`).
- Find caches the folded text and its maps per text and fold flag, maps hits to spans in one forward walk, and searches only the story open for editing (`document-find.ts`).
- Local paint descriptors for pending redlines never enter model storage or review decisions (`document-pending-redlines.ts`).
- A range edit whose head is revision-only has no run to join into and is refused before paint shows it (`document-range-edits.ts`).
- For downloads, `filename*` is authoritative for a non-ASCII name and `filename` is the fallback (`document-workspace-downloads.ts`).
- A surface with no save leaves the platform's own Ctrl/Cmd+S unclaimed (`document-workspace-keys.ts`).
- Local recovery acknowledges a commit before any refetch can delay it (`document-workspace-mutations.ts`).
- A paired read is fetched only once both sides are picked (`document-workspace-queries.ts`).
