# Whole-subsystem test-audit campaign

Read this only for an explicitly requested broad audit of one Obiter subsystem. The ordinary skill's value, retention, safety, and validation gates still apply. Use several small, independently reviewable changes when that keeps coverage easier to verify; one large PR is not a success condition.

1. **Pin and baseline.** Fetch the actual base and record its SHA, all owned test files and executable QA scenarios, pass/fail/skip state, test/support/production line counts, runner configuration, and timing under a safe isolated environment. Treat baseline failures as possible product defects, not deletion opportunities.
2. **Partition by behaviour owner.** Inventory API, UI, worker, storage, contract, build/release, and end-to-end boundaries relevant to the subsystem. Assign each test and parameter row one owner; include tests located in shared packages and scripts. Avoid partitioning solely by folder name.
3. **Build a read-only ledger.** Read each complete test and its production path. Mark each assertion or table row **retain**, **fix**, **consolidate**, or **delete**, with the protected contract, plausible regression, and evidence. When rows of a parameter table protect different risks, mark them separately.
4. **Plan keepers before edits.** A second pass checks where the same contract is replayed through weaker mocks. Name the strongest keeper for each contract, any distinct lower- or higher-layer risk that still requires its own test, the assertion to move, and test-only production seams that can disappear. Uncertain cases remain retained.
5. **Edit one owner boundary at a time.** Serialize shared harness changes. Preserve deterministic synthetic fixtures and isolated databases. Never weaken CI routing or remove a suite simply because its path changed. Keep unrelated product bug fixes separate from test consolidation.
6. **Preservation review.** Independently compare removed contracts with keepers. Challenge each keeper with a safe deliberate production mutation where warranted, especially for legal correctness, auth, isolation, audit, data loss, and rollback. Restore source exactly. A keeper that cannot fail the claimed bug is not proof.
7. **Reconcile and report.** Rebase or merge the current base according to the repository's active workflow, then recheck new regressions added while the campaign ran. Run the full relevant Bun suite and real boundary checks. Report preserved contracts, restored gaps, baseline versus final counts and timings, and test/support versus production LOC separately. Stop if review confidence is lower than before the campaign.

The OpenClaw [test-audit](https://github.com/openclaw/openclaw/blob/main/.agents/skills/test-audit/SKILL.md) and [campaign](https://github.com/openclaw/openclaw/blob/main/.agents/skills/test-audit/CAMPAIGN.md) guides informed the owner-boundary ledger. This Obiter version deliberately replaces their Vitest-specific validation and adds Obiter's legal-data, isolation, Bun, and rollback constraints.
